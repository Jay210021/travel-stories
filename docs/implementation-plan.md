# 缺少功能與實作順序

## P0：核心作者流程

1. 新文章表單實際寫入 Supabase，而非只顯示暫存訊息。
2. 支援標題、正文、分類、國家、城市、景點、旅程系列與原始日期。
3. 儲存草稿後可預覽，再由作者發布。
4. 表單提供載入、成功與失敗狀態，避免重複送出。

## P0：文章媒體

1. 照片上傳後建立 `story_media` 關聯，保存排序、封面、說明及替代文字。
2. 影片先使用現有 Supabase Storage，建立可在文章頁與影片專區共用的媒體紀錄。
3. 發布前提示作者檢查照片 GPS／隱私資訊。

## P1：Facebook 匯入

1. 已支援既有備份檔手動匯入，保留原始 `publishedAt`、整理後標題與 `source_id`。
2. 已新增啟用後新貼文的 Webhook 自動草稿、每日補漏、圖片搬移與冪等處理。
3. 已新增目前匯入狀態、成功與失敗的 Facebook 匯入嘗試紀錄、最多三次自動重試及人工重試。
4. 真實連線仍需依 `facebook-auto-import-setup.md` 建立 Meta App、Page Token 與 Webhook。

## P1：刪除與復原

1. 草稿管理加入移至垃圾桶操作。
2. 垃圾桶列出 `status = trash` 且未超過 30 天的文章。
3. 支援復原；超過 30 天的永久清理交由排程 SQL 執行。

## P1：閱讀統計

1. 建立匿名、文章層級的每日瀏覽事件，不保存單一訪客身分。
2. 文章頁記錄瀏覽；後台顯示總瀏覽、熱門文章、熱門國家與近期趨勢。

## P1：後台權限與體驗

1. 所有後台資料操作沿用 Supabase RLS 與作者 allowlist。
2. 統一後台導覽、登入檢查、空狀態、載入狀態與錯誤訊息。
3. 移除不實的展示狀態；備份與 Email 通知在沒有外部服務時明確標為尚未設定。

## 外部依賴

- Google OAuth 需在 Supabase Dashboard 設定 provider 與 callback URL。
- Email 通知需要另選郵件服務與 API key，未設定前不假裝已寄送。
- Cloudflare Stream 需要帳號與 token；第一版影片先使用 Supabase Storage，日後可替換。
- 自動備份需要 Supabase PITR、平台備份或外部排程，程式只能顯示真實可取得的狀態。
